# Pipnote

Turn photos and videos of your notes into revision material. Pipnote reads the text in
your upload, then builds a summary, ten flashcards, a five-question quiz and three
exam-style questions that can be answered and AI-marked.

Built for one small group of friends. Everyone signs in separately and only sees their
own study sets.

## Stack

- **Vite + React 19 + TypeScript** — the frontend
- **Tailwind CSS v4 + shadcn/ui** — the interface
- **Convex** — database, file storage, server actions and user accounts
- **Convex Auth (email one-time code)** — separate accounts without password management
- **NVIDIA API** — every AI request (chat completions at `integrate.api.nvidia.com`)
- **Bun** — package manager and scripts

There is no separate server to deploy: Convex hosts the backend, file storage and AI
actions.

## What version 1 does

1. **Upload notes** — photos (JPG/PNG), a video (six frames are sampled in the browser),
   or pasted text.
2. **Pip generates** — a structured summary, flashcards, a multiple-choice quiz and
   exam-style written questions with marking guides.
3. **Study** — flip and self-rate flashcards, take the quiz with explanations, and write
   exam answers that NVIDIA marks with feedback and a model answer.
4. **Everything is saved** — sets, extracted notes, uploads, card progress and quiz scores
   persist between sessions, in the account that created them.

The dashboard after sign-in is **My study sets**.

## Run it

### In this Freebuff environment

The Vite dev server and Convex deployment are already managed. Open the preview, add the
NVIDIA key (below), and use the app. No terminal process needs to be started.

### Locally

```bash
bun install

# 1. Start the Convex dev deployment (creates/links a deployment and regenerates types)
bunx convex dev

# 2. In a second terminal, start Vite
bun dev
```

`bunx convex dev` writes the deployment URL into the project's environment. This template
already has Convex Auth configured (email OTP and guest sign-in); a fresh Convex
deployment needs the auth environment keys generated by the first `convex dev` run.

Open the printed local URL (usually `http://localhost:5173`).

### Checks

```bash
bun tsc -b --noEmit     # frontend + Convex types
bunx convex dev --once  # push functions and regenerate types
bun run lint            # ESLint (the template's own UI primitives have pre-existing findings)
```

## Supply the NVIDIA key

The key must never be committed or shipped to the browser. It is only read on the Convex
server — by server actions for AI calls, and by a status query that checks whether it
exists. The environment variable is named **`NVIDIA_API_KEY`** everywhere.

### Option A — environment variable (preferred)

Set it on the Convex deployment:

```bash
npx convex env set NVIDIA_API_KEY nvapi-your-key-here
```

On Freebuff, add `NVIDIA_API_KEY` in the project's **Keys** tab instead. The value is
available to Convex functions as `process.env.NVIDIA_API_KEY`.

This is the shared key for the whole app: friends do not need their own NVIDIA accounts.
Usage is billed to whoever owns the key.

### Option B — the AI setup screen (fallback)

If `NVIDIA_API_KEY` is not present in the environment, sign in and open **AI setup** (or
the prompt on the dashboard). Paste the key there. The app:

1. verifies it with a tiny NVIDIA request,
2. stores it in a Convex table that only server functions can read,
3. never returns it from a query, never logs it, and never writes it to browser storage.

The environment variable always wins over a saved fallback key. To rotate a saved key,
open AI setup again. To remove it, delete the `appSettings` record for `NVIDIA_API_KEY`
in the Convex dashboard.

Get a key from [NVIDIA Build](https://build.nvidia.com/).

### Optional model overrides

NVIDIA retires models periodically. Defaults (chosen from currently available hosted
endpoints):

| Purpose | Environment variable | Default |
| --- | --- | --- |
| Summaries, cards, quizzes, exams | `NVIDIA_TEXT_MODEL` | `nvidia/nemotron-3.5-lightning-30b-a3b` |
| Reading photos / video frames | `NVIDIA_VISION_MODEL` | `meta/llama-3.2-90b-vision-instruct` |

Set overrides on the Convex deployment the same way as `NVIDIA_API_KEY`. If a model is
retired, the app shows a clear "model not available" message and the README's env var is
the fix.

## How a set is generated

- Creating a set saves it immediately with status **queued**.
- Opening the set triggers one server action. An atomic claim prevents double runs.
- The action reads stored images (one vision request per image), writes extracted notes to
  the set, then sequentially asks NVIDIA for the summary, flashcards, quiz and exam
  questions. Progress messages are written to the set so the page updates live.
- If anything fails, the set gets an **error** status, a friendly message and a Retry
  button. Extracted notes and uploads are kept.
- NVIDIA rate limits (HTTP 429) and server errors are retried briefly with backoff, then
  reported with a clear message. Authentication failures point at AI setup.

Convex actions can run for several minutes, so generation continues even if the page is
closed; re-opening the set shows the saved result.

## Assumptions made for version 1

- **Video = sampled frames, not audio.** Six frames are captured in the browser and only
  those JPEGs are uploaded. Lecture slides, whiteboards and pages you pan over work best;
  talking-head audio is not transcribed. Photo uploads are the fallback.
- **Up to 8 photos per set**, compressed to a 1600px JPEG before upload. Skipping a PDF
  file input keeps the upload path dependable in the browser.
- **Fixed amounts**: 10 flashcards, 5 quiz questions and 3 exam questions. Keeping the
  counts fixed makes generation predictable and affordable on a shared key.
- **Accounts are email-code based.** No passwords. Guest sign-in exists for quick demos,
  but guest sets only survive that browser session; use email to keep sets recoverable.
- **Sets are private.** There is no sharing or group folder in version 1; friends have
  separate accounts and separate libraries.
- **One shared NVIDIA key** for the deployment. Any signed-in friend can update the saved
  fallback key from AI setup.
- **English prompts and defaults**, with at most 60,000 characters of pasted notes stored
  (12,000 characters sent to the model per generation call).
- No spaced-repetition scheduling: cards are self-rated and mastery is tracked, which is
  enough for focused revision without a second scheduling system.

## Troubleshooting

- **"NVIDIA_API_KEY is not set"** — add it in AI setup or on the Convex deployment.
- **401/403** — NVIDIA rejected the key. Replace it in AI setup.
- **429** — rate-limited. Wait about a minute, then Retry on the set.
- **404 / 410 model not available** — NVIDIA retired that model. Set
  `NVIDIA_TEXT_MODEL` / `NVIDIA_VISION_MODEL` to a model currently listed on NVIDIA Build.
- **The key is verified but generation fails** — the verification call only proves the key
  works; if a specific model is retired you'll see the 410 message above.
- **Poor OCR** — use straighter, brighter photos; dark handwriting or blurry frames are
  the usual cause. Pasted text is the most reliable input.
